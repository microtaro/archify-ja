# Archify 日本語派生版 設計

## 目的

Archify v2.16.0を基準に、日本語利用者が導入、作図、検証、修正、保守まで日本語で完結できる独立Skill `archify-ja` を作成する。

これは本家へ継続追従するフォークではない。特定時点のArchifyを基にした日本語スナップショット派生版として公開し、日本語版に必要な保守だけを行う。

## 公開上の識別

- リポジトリ: `microtaro/archify-ja`
- Skill ID: `archify-ja`
- 製品表示名: Archify 日本語版
- 初版: `2.16.0-ja.1`
- 派生元: `tt-a1i/archify` v2.16.0、commit `5de7275`
- ライセンス: MIT
- 本家の著作権表示と許諾文を保持し、日本語派生版の表示を追加する。
- README冒頭で非公式の日本語派生版であることと、継続同期を保証しないことを明示する。

本家と日本語版を同時に導入できるよう、Skill名、配布物、生成物のgenerator表示、リリース識別子を分離する。元のJSONフィールド名、CLIサブコマンド、CLIオプション、JavaScript識別子、機械可読な診断コードは互換性と保守性のため変更しない。

## 日本語化の範囲

### 完全に日本語化するもの

- `archify/SKILL.md`
- `archify/references/*.md`
- README、導入、更新、削除、基本操作の説明
- Viewerのボタン、メニュー、凡例、ヘルプ、状態、エラー、アクセシビリティ文言
- CLIのusage、利用者向けエラー、診断説明、修正候補
- JSON Schemaの利用者向け説明文
- 日本語サンプルと主要テストデータ

日本語利用者がSkillの動作を自分で理解し、修正できることを公開条件とする。コードを読まなければ分からない重要な運用規則を英語文書だけに残さない。

### 日本語向けに調整するもの

- `meta.locale: "ja-JP"` を正式なロケールとして追加する。
- 日本語版では日本語を既定とする。
- HTMLとSVGの`lang`、Viewer固定文言、ARIA、凡例、検証メッセージをロケールと一致させる。
- 日本語フォントスタック、行高、折返し、禁則、CJK幅計算を調整する。
- PNG、SVG、WebM、Share Cardで文字化け、欠落、重なりがないことを確認する。
- authored contentは自動翻訳せず、入力された文言をそのまま保持する。

### 原文を保持するもの

- JSONフィールド名
- CLIサブコマンドとオプション名
- JavaScriptの識別子
- 機械可読な診断コード
- ブランド名、製品名、規格名
- 原著作権表示
- 過去のCHANGELOGと研究記録

内部コードコメントは、日本語利用者が変更する主要箇所では必要に応じて日本語補足を加えるが、全面翻訳の対象にはしない。

## 文字数と表示制約

英語向けの文字数制限を日本語へ機械的に適用しない。一方、すべての上限を無条件に削除することもしない。各制約を次の3種類に分類する。

1. 外部仕様による制約
   - Agentランタイム互換性のためのSkill description 1024文字・1024バイト上限など。
   - 互換性のため維持し、日本語文面を制約内で簡潔に記述する。
2. 安全性・情報設計上の制約
   - 修正回数、表示する主要コンポーネント数、比較対象数など。
   - 言語と無関係なため原則維持する。
3. 英語の表示幅を前提とした制約
   - ラベル48/80文字、注釈140文字、短文化の指示など。
   - 日本語の実描画結果を基に、文字数ではなく表示領域、折返し、衝突の検査へ寄せる。

検証を通すためだけに意味のある日本語を削らない。まずノード幅、行数、行高、余白、経路、図の分割を修正し、意味を保てる場合に限って文言を短くする。

`SKILL.md` の行数上限は入口文書を小さく保つ意図として扱う。日本語で保守不能になる場合は上限を緩和できるが、まず詳細規則を日本語の参照文書へ分離する。

## 実装構成

### 1. 派生版の識別

パッケージ、Skill、ZIP、生成物メタデータ、README、リリース検査に含まれる本家固定値を洗い出し、`archify-ja` の識別へ変更する。本家の更新マニフェストを参照しない。

初版では独自の更新サービスを作らない。更新確認は無効化し、存在しない更新先や本家へ意図せず通信しない。将来更新通知を導入する場合は、日本語版のリポジトリと不変な配布物を指す独立契約として設計する。

### 2. 日本語ロケール

既存のi18nテーブルとロケール解決処理へ`ja-JP`を追加する。既存の`en`と`zh-CN`は回帰防止対象として残す。日本語版の既定値と、ロケールを明示したときの挙動を分けてテストする。

### 3. 日本語の執筆契約

Skill入口と参照文書を日本語化し、事実を創作しない、型付きIRを維持する、検証後の成果物を変更しない、実ブラウザで確認する、といった本家の安全契約を保持する。

翻訳によって規則の強度を変えない。英語固有の簡潔さと、日本語で意味を保つために必要な情報量が衝突する箇所だけ、日本語向けの規則へ置き換える。

### 4. 導入と削除

READMEにはCodex、Cursor、Claude Code、OpenCodeについて、次を対で掲載する。

- グローバル導入
- プロジェクト限定導入
- 導入確認
- 更新または再導入
- アンインストール
- 手動導入した場合の削除場所

コマンドは公開時点の`skills` CLIを隔離した一時環境で実行して確認する。正式な削除コマンドが存在する場合はそれを優先し、存在しない場合だけAgentごとの手動削除手順を記載する。推測したコマンドは掲載しない。

RavenとDeepSeek Harnessは初版の配布対象外とし、対応済みと誤認されないよう明記する。

## 検証

### 自動検証

- 既存テストを派生版の識別へ更新して実行する。
- `ja-JP` のSchema受理と不正ロケールの拒否を確認する。
- Viewer UI、凡例、ARIA、HTML/SVG `lang` の日本語化を確認する。
- CLI usage、診断、修正候補の日本語表示を確認する。
- 本家URLや本家更新マニフェストが配布物に残っていないことを検査する。ただし、派生元表示、著作権、ライセンス上必要なURLは除外する。
- 本家と日本語版の同時導入でSkill IDや保存先が衝突しないことを確認する。
- クリーンなRelease ZIPだけからdoctor、validate、deliverが動作することを確認する。

### 成果物検証

Architecture、Workflow、Sequenceの日本語サンプルを生成する。デスクトップと狭幅で実ブラウザ表示を確認し、少なくとも次を検査する。

- 日本語の文字化け
- ラベル、注釈、凡例の切れと重なり
- 不自然な単語途中の折返し
- Viewer操作とキーボード操作
- light/darkテーマ
- PNGとSVG出力
- `prefers-reduced-motion`

Data FlowとLifecycleは共通Viewerとロケール契約の自動検証対象に含める。初版の手動表示確認は代表3形式を必須とし、共通処理以外に形式固有の変更が生じた場合はその形式も追加する。

### 導入検証

一時的なユーザー領域とプロジェクト領域を使い、各Agentについて導入、一覧表示、呼び出し可能性、削除、削除後の不存在を確認する。外部公開前のGitHub URLを必要とする検証は、ローカルパスまたはRelease候補アーカイブで先に行い、公開後に公開URLから再確認する。

## 公開手順と権限境界

実装とローカル検証まではこの作業リポジトリで行う。以下は外部状態を変更するため、実行直前にユーザーの明示的な許可を得る。

- GitHub上で`microtaro/archify-ja`を作成する。
- remoteを追加または変更する。
- pushする。
- GitHub Releaseを作成する。
- 公開URLからインストール検証を行う。

リポジトリ履歴は本家から保持する。これにより派生関係、基準コミット、日本語版で加えた変更をGit履歴から追跡できるようにする。

## 非目標

- 本家Archifyの将来リリースへの自動追従
- 全研究記録と過去CHANGELOGの翻訳
- JSONフィールド名やCLIコマンドの日本語化
- 初版での独自Webサイトおよび更新配信基盤
- RavenおよびDeepSeek Harness向け配布
- 日本語版独自の図形式や、本家にない推論機能の追加

## 完了条件

- 日本語利用者が日本語文書だけで導入、作図、検証、修正、削除できる。
- 日本語のViewer UI、CLI、生成物が実際に動作する。
- 日本語ラベルを意味を損なう短縮なしで扱える。
- 本家と同時導入でき、更新先と配布識別が混ざらない。
- 既存の型付きIR、安全契約、決定論的検証を維持する。
- 検証済みのRelease ZIPと、実証済みの導入・削除手順を公開できる。
